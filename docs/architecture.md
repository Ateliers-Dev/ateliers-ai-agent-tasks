# 全体構成と運用方針

## ドキュメントの配置

- `docs/<project>/` に、プロジェクトの概要、共有方針、関連資料への参照など、AI サービス間で共有する情報を置く。
- `docs/<project>/<provider>/` に、AI サービス固有の補足や参照先を置く。共通情報はプロジェクト直下の文書へリンクする。
- アプリ本体の詳細設計は開発リポジトリで管理し、必要に応じて共通コンテキストから参照する。

共有方針と引き継ぎ情報の正本は GitHub のドキュメントとする。チャット履歴やメモリは、経緯の確認や作業の補助に使う。

## 全体計画とフェーズ別実装

全体計画には、目的、フェーズの順序、依存関係、完了条件をまとめ、プロジェクト直下で管理する。各フェーズの具体的な作業範囲と検証条件は、全体計画への参照を添えて Issue に記載する。チャットを分ける場合も、各チャットから同じ計画と Issue を参照できるようにする。

## Issue 起点の作業記録

GitHub Issue を AI タスクの起点とし、`reports/<year>/issue-<number>/` に作業記録を置く。記録から対象 Issue と関連する変更をたどれるようにする。

| ファイル | 記録する内容 |
| --- | --- |
| `investigation.md` | 現状、調査結果、判断の根拠 |
| `implementation.md` | 実装内容、変更の理由、関連コミットや PR |
| `validation.md` | 検証方法、結果、未実施の項目 |
| `review.md` | レビュー所見、対応状況、残課題 |
